# Echo of Souls — техническая документация

Этот файл — точка входа для любого, кто впервые открывает проект,
включая вас самого через полгода. Если что-то из описанного ниже
разойдётся с реальным кодом — README не прав, а не код: поправьте
файл при следующем удобном случае.

## Архитектурные решения

Все значимые решения зафиксированы в `docs/adr/` по одному файлу на
решение. Начните с них, если непонятно, почему что-то устроено именно
так:

- [`ADR-001`](adr/ADR-001-engine-version.md) — Unity 6.3 LTS, почему и на каких условиях обновляем версию
- [`ADR-002`](adr/ADR-002-layer-boundaries.md) — семь сборок, границы зависимостей, три области Composition Root
- [`ADR-003`](adr/ADR-003-tech-stack.md) — что из стека реально подключено, что только запланировано

Более широкий контекст — архитектурные обоснования, оценка объёма
работ, паттерны — в документе «План технической разработки» (вне
репозитория, у геймдизайнера/в общей папке проекта).

## Структура проекта

```
Assets/_Project/
  Domain/            Echo.Domain            — правила игры, чистый C#
    Common/            типизированные идентификаторы: EntityId, AbilityId, ItemId
    Events/            IEventBus, EventBus, Subscription
  Application/       Echo.Application       — сценарии поверх домена
    Run/               RunContext — состояние одного прохождения
    Session/           SessionContext — состояние сессии
    World/             RegionContext — состояние текущего региона
  Infrastructure/    Echo.Infrastructure    — реализации портов (по мере подключения)
  Presentation/      Echo.Presentation      — вью, UI, анимации
  Composition/       Echo.Composition       — корень композиции
    Scopes/            AppScope, GameplayScope, RegionScope
    EntryPoints/       BootEntryPoint + пробы для ручной проверки времени жизни областей
    Debug/             ScopeDebugPanel
    Diagnostic/
  Content/           Echo.Data               — ScriptableObject-ассеты
  Editor/            Echo.Editor             — инструменты редактора
  Tests/
    Domain/            Echo.Tests.Domain — EditMode, без Play Mode
    Play/              Echo.Tests.Play   — PlayMode, дымовые тесты
docs/
  adr/                 журнал архитектурных решений
  README.md            этот файл
```

Правило простое: если новый класс относится к правилам игры и не
использует `UnityEngine` — он в `Domain`. Если он — про то, как это
выглядит и ощущается, — в `Presentation`. Подробности и промежуточные
случаи — в `ADR-002`.

## Как запустить тесты

- **EditMode** (быстрые, домен): `Window → General → Test Runner →
  EditMode → Run All`. Не требуют Play Mode, весь набор укладывается
  в секунды.
- **PlayMode** (медленные, интеграционные): та же панель, вкладка
  `PlayMode`. Пока пуста — появятся начиная со спринта, где будет
  что интегрировать целиком.

Правило: перед коммитом EditMode-тесты должны быть зелёными. Если
тест специально сломан в процессе работы — не коммитить, пока не
починен или явно не помечен `[Ignore]` с причиной в комментарии.

## Отладочные инструменты

- **`ScopeDebugPanel`** (`Composition/Debug/`) — панель для проверки
  жизненного цикла `AppScope` / `GameplayScope` / `RegionScope` в
  Play Mode.
  *[Уточнить: как открывается — горячей клавишей, отдельным окном
  редактора или объектом на сцене — и что именно показывает. Дописать
  сюда после того, как устоится финальный вид панели.]*
- **`AppScopeProbe` / `GameplayScopeProbe` / `RegionScopeProbe`**
  (`Composition/EntryPoints/`) — служебные компоненты для ручной
  проверки, что каждая область создаётся, видит родителя и корректно
  уничтожается. Используются вместе с `ScopeLifetimeTest`.
- **`BootOnPlay`** (`Editor/`) — обеспечивает запуск игры с загрузочной
  сцены независимо от того, какая сцена открыта в редакторе.
  *[Уточнить: требует ли это отдельного объяснения для сценариста/
  дизайнера, если они будут запускать проект сами.]*

## Соглашения

- `.editorconfig` в корне репозитория — форматирование не обсуждается.
- Идентификаторы сущностей — типизированные (`EntityId`, `AbilityId`,
  `ItemId`), не голые строки. Не заводить новый идентификатор как
  `string` — заводить как `readonly record struct` по образцу
  существующих в `Domain/Common/`.
- Подписка на `IEventBus` всегда возвращает `IDisposable`; отписка —
  обязательна при уничтожении подписчика.
- Коммиты — короткими, с понятным сообщением на русском или английском
  (выбрать один язык и придерживаться его; в проекте пока нет
  сложившейся практики — *[дозаполнить, когда появится]*).
