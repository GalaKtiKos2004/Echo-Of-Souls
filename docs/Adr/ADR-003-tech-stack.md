# ADR-003: Стек пакетов

Дата:    2026-08-17
Статус:  Принято (частично) — дополняется по мере подключения пакетов

## Контекст

Полный список инструментов для проекта обсуждался в архитектурном
документе заранее — там оценивались все кандидаты сразу. Здесь
фиксируется только то, что **реально подключено и используется** на
день 7. Остальное намеренно не фиксируется как решённое: пакет,
записанный в ADR до того, как с ним написана хоть одна строчка кода,
создаёт ложное чувство, что выбор уже проверен на практике.

Правило пополнения этого ADR: пакет попадает сюда в тот день, когда
он действительно подключён и на нём написан первый работающий код —
не раньше.

## Решение — уже подключено и используется

| Пакет / инструмент | Роль | Где используется |
|---|---|---|
| **VContainer** | Внедрение зависимостей, Composition Root | `Echo.Composition`: `AppScope`, `GameplayScope`, `RegionScope` |
| **Unity Test Framework + NUnit** | Тесты EditMode | `Echo.Tests.Domain`: тесты идентификаторов, шины событий, времени жизни областей |
| **Git + Git LFS** | Контроль версий, бинарные ассеты | Весь репозиторий, настроено в день 1 |

## Последствия

+ ADR отражает реальность репозитория, а не пожелания из документа
  верхнего уровня — по нему можно проверить состояние проекта, не
  открывая код.
+ Решение о каждом пакете принимается в контексте задачи, которую он
  решает, а не абстрактно.
- Документ требует дисциплины: если пакет подключили в спешке и забыли
  дописать строку — ADR начинает врать. Проверять раз в спринт вместе
  с закрытием критерия готовности.
